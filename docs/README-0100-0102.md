# OHBONO Wallet — Batch 0100–0102

This batch completes the first customer-visible refund layer and introduces
explicit payment-state reconciliation.

## Customer

```text
My Wallet
   |
   +---- Transaction History
   |
   +---- Refunds & Reversals
```

## Payment state

```text
awaiting_payment
       |
       v
wallet_captured
       |
       +----> paid
       |
       +----> partially_paid
       |
       +----> reconciliation_required
                         |
                         v
                     reversed
```

## Important separation

Financial transactions are immutable:

```text
wallet_transaction
```

Payment workflow state is mutable:

```text
wallet_payment_state
```

This separation is intentional.

## Admin

The reconciliation screen is a review queue. It does not automatically
reverse wallet funds.

An administrator or a future controlled reconciliation worker should inspect
the external payment state before approving a reversal.
