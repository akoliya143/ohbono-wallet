# OHBONO Wallet — Staging Integration 0109–0111

## Scope

This batch adds the integration boundary for OpenCart 4.1.x without changing
OpenCart core files.

The important rule is:

> Events prepare or synchronize state. They do not independently deduct wallet
> funds.

## Event strategy

The wallet integration is divided into three concerns:

1. Checkout preparation
2. Order creation/state synchronization
3. Final wallet capture

Only #3 is allowed to mutate the wallet, and it must call the server-side
wallet payment service with a trusted order.

## Journal Theme 3.2

Journal checkout customizations can alter the normal checkout route and DOM.

Therefore:

- Do not assume a specific Journal DOM selector.
- Do not hard-code a Journal template override in this batch.
- Keep wallet calculation/payment endpoints independent of the presentation.
- Add the wallet UI through the site's configured Journal checkout mechanism
  after confirming the actual checkout layout.

## Staging checklist

### Installation

- [ ] Backup database.
- [ ] Backup OpenCart files.
- [ ] Upload extension files.
- [ ] Run extension installation.
- [ ] Confirm schema diagnostics returns valid.
- [ ] Confirm no OpenCart core file was modified.

### Admin

- [ ] Log in as full administrator.
- [ ] Confirm Wallet menu appears through the supported extension mechanism.
- [ ] Confirm reconciliation is readable.
- [ ] Confirm refund action is restricted.
- [ ] Confirm diagnostics is readable.
- [ ] Test a non-authorized admin group.

### Customer

- [ ] Create a test customer.
- [ ] Credit a known wallet amount.
- [ ] Confirm wallet balance.
- [ ] Confirm wallet history.
- [ ] Confirm refund/reversal history.

### Checkout

- [ ] Wallet-only order.
- [ ] Partial wallet order.
- [ ] Zero-wallet order.
- [ ] Wallet amount greater than order total.
- [ ] Insufficient wallet balance.
- [ ] External payment success.
- [ ] External payment failure.
- [ ] Retry same payment reference.
- [ ] Browser refresh during payment.

### Accounting

For every test:

```text
Wallet balance before
        ↓
Wallet debit/credit
        ↓
Wallet balance after
        ↓
Order/payment state
        ↓
Transaction reference
```

All four must agree.

## Rollback

If staging fails:

1. Stop checkout testing.
2. Preserve transaction rows/logs.
3. Disable the wallet payment method.
4. Do not delete wallet financial records.
5. Diagnose the specific order/payment state.
