# OHBONO Wallet — Batch 0091–0093

This batch moves wallet payment from preview/calculation into final,
server-side authorization.

## Secure flow

```text
Customer Checkout
       |
       v
Trusted Order Total
       |
       v
Wallet Amount Validation
       |
       v
Generate Stable Payment Reference
       |
       v
START TRANSACTION
       |
       +--> Find existing reference?
       |       |
       |       +--> YES: return existing transaction
       |
       +--> Lock wallet row
       |
       +--> Recheck current balance
       |
       +--> Deduct wallet amount
       |
       +--> Insert wallet transaction
       |
       v
COMMIT
```

## What is protected

- Browser cannot define the wallet balance.
- Wallet balance is re-read from the database.
- Concurrent wallet payments lock the wallet row.
- A debit cannot exceed the current balance.
- Repeated payment requests with the same trusted reference are idempotent.
- Wallet deduction and transaction logging occur in one database transaction.

## Important OpenCart integration boundary

The exact OpenCart checkout/payment controller for the project must call this
service only after it has the authoritative order total and a stable order
payment reference.

Do not deduct wallet funds from a display-only AJAX endpoint.
