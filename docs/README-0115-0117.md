## Event registry

The event registry is idempotent. Existing event codes are reused rather than
duplicated.

## Financial authority

Only the server-side wallet payment service can mutate balances.

The Journal JavaScript only sends user-selected input to the trusted checkout
flow.

## Staging scenarios

At minimum, test:

1. Wallet-only payment
2. Partial wallet + external payment success
3. Partial wallet + external payment failure
4. Insufficient wallet balance
5. Wallet amount above order total
6. Same callback repeated
7. Browser refresh after callback

## Success criteria

A staging test passes only when:

```text
Order state
+
Wallet transaction
+
Wallet balance
+
Payment state
+
Reference/idempotency
```

all agree.
