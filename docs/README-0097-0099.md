# OHBONO Wallet — Batch 0097–0099

This batch adds the compensation layer required for wallet payments.

## Why this is necessary

Wallet and external payment providers are separate systems. A partial order
can therefore reach this state:

```text
Wallet capture       = SUCCESS
External payment     = FAILED
Order                 = NOT PAID
```

The wallet amount cannot simply disappear.

## Compensation flow

```text
Wallet capture
     |
     v
External payment fails
     |
     v
Reconciliation required
     |
     v
Approved reversal
     |
     v
Wallet credited
```

## Accounting rule

Never edit or delete an original financial transaction.

Instead:

```text
DEBIT  wallet_payment
   +
CREDIT wallet_reversal
```

Both remain permanently visible in transaction history.

## Safety

- Reversal requires the original debit.
- Reversal locks the wallet.
- Reversal uses a unique reference.
- Reversal is atomic.
- Reversal creates an audit entry.
- Refunds require an explicit reason.
- Reconciliation does not automatically move money.
